## Why this document exists

`empireoe-core.lead_router` knows how to:
- receive Meta webhook events (Instagram DM + WhatsApp Business)
- classify the message with Claude (recruitment / study_abroad / agent / general)
- persist via the product backend's `on_lead` callback
- ping the assignee's Slack channel (new in v0.6.0)

What it doesn't know yet is the **rule table** — the mapping from
`(source, category, product)` to `(assignee, slack_channel, follow-up SLA)`.

This file is the source of truth. Ops mirrors these values into env vars on each backend host.

## Out-of-hours rule

**Rule: queue + auto-reply. No live routing after 18:00 IST.**

Auto-reply sent by Claude via WA / IG DM:
> "Thanks for reaching out to Team Empire 👋 Our team is available 9am–6pm IST,
> Mon–Sat. We'll get back to you first thing on the next business day!"

Lead is persisted to the DB as normal. Slack channel ping is **suppressed** outside
business hours. Time-gated notification (ping at 09:00 IST next business day) is
tracked as v0.6.x backlog — requires `notify_lead_arrived()` to accept a `schedule_at` param.

## Escalation (SLA breach)

## Env vars to set per backend (Ops)

Once webhook URLs are generated by Mano, set on each backend host:

```
# Per-channel Slack webhooks
SLACK_WEBHOOK_URL_LEADS_RECRUITMENT=https://hooks.slack.com/services/...
SLACK_WEBHOOK_URL_LEADS_DEFAULT=https://hooks.slack.com/services/...
SLACK_WEBHOOK_URL_LEADS_HOTELO=https://hooks.slack.com/services/...
SLACK_WEBHOOK_URL_LEADS_LWE=https://hooks.slack.com/services/...
# Private — agents channel only (Sravan + Harish):
SLACK_WEBHOOK_URL_LEADS_AGENTS=https://hooks.slack.com/services/...

# Product slug — so the router consults SLACK_WEBHOOK_URL_LEADS_<PRODUCT>
# before falling back to the default.
LEAD_ROUTER_PRODUCT_SLUG=empireo   # or eoe, hotelo, lwe, etc. per host
```

After updating: `sudo systemctl restart <service>`.

## Generating the webhook URLs (one-time, Mano)

For each Slack channel above:
1. Open https://api.slack.com/apps → Team Empire workspace app
2. Incoming Webhooks → Add New Webhook to Workspace → pick the channel
3. Copy the `https://hooks.slack.com/services/...` URL
4. Drop into 1Password under the slot in the channel-inventory table above

> Verify #leads-agents is private before generating its webhook.

## Verifying (post-deploy smoke test, Sravan)

```bash
# Fire a synthetic recruitment-category WhatsApp event.
# Should produce a Slack post in #leads-recruitment within 2-3 seconds.
curl -X POST -H 'Content-Type: application/json' \
  https://api.empireo.ai/api/v1/webhooks/meta/whatsapp \
  -d '{"entry":[{"changes":[{"value":{"messages":[{"type":"text",
       "text":{"body":"Looking for senior frontend role in Dubai"},
       "from":"+919876543210"}],"contacts":[{"wa_id":"+919876543210",
       "profile":{"name":"Test User"}}]}}]}]}]}'
```

If no Slack post appears, check:
- `journalctl -u <service> -n 50` for `Slack webhook not configured` or non-2xx warnings
- That `SLACK_WEBHOOK_URL_LEADS_RECRUITMENT` is set in the env
- That the webhook URL is still valid (Slack invalidates on app revoke)
